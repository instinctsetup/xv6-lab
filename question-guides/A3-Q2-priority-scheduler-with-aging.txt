xv6 OS LAB - ASSIGNMENT 3, A3 Q2: Priority scheduler with aging
================================================================

WHAT THE QUESTION ASKS
----------------------
Priority field 1 (highest) to 20 (lowest), default 10, a set_priority() syscall, always run the lowest priority number, ties round-robin, and aging: a process waiting more than 30 ticks gains one priority level.

HOW TO BUILD AND RUN
--------------------
Build and boot:   make clean && make SCHED=PRIO qemu CPUS=1
At the xv6 shell: priotest

WHICH FILES TO OPEN / SHOW
--------------------------
proc.c (effective_priority(), sched_tick(), AGING_INTERVAL in sched.h), sysproc.c (set_priority/get_priority)

EXPECTED OUTPUT
---------------
Higher priority finishes first (verified: priorities 2, 10, 17 in order), and the lowest-priority process still completes because aging lifts it.

----- proc.c - effective_priority() -----
// Aging (A3 Q2 / A7 Q4): a process that has waited more than
// AGING_INTERVAL ticks in RUNNABLE gets one priority level better.
static int
effective_priority(struct proc *p)
{
  int pr = p->priority;
  if(pr > 1 && ticks - p->ready_since > AGING_INTERVAL)
    pr--;
  return pr;
}

----- proc.c - key(), PRIO case -----

----- proc.c - sched_tick() aging -----
// Periodic bookkeeping for the preemptive dynamic policies.
// Called from trap.c on timer ticks with ptable.lock NOT held, so we take
// it here. Walking the table once per tick is O(NPROC) and fine for xv6.
void
sched_tick(void)
{
  struct proc *p;

  if(SCHED != SCHED_PRIO && SCHED != SCHED_MLFQ)
    return;
  acquire(&ptable.lock);
  for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){
    if(SCHED == SCHED_PRIO){
      // A3 Q2/A7 Q4 aging: persist the effective-priority improvement so
      // long-waiting processes ratchet upward level by level.
      if(p->state == RUNNABLE && p->priority > 1 &&
         ticks - p->ready_since > AGING_INTERVAL){
        p->priority--;
        p->ready_since = ticks;
      }
    } else {
      // A4 Q3 MLFQ: periodic priority boost prevents starvation.
      if(ticks > 0 && ticks % MLFQ_BOOST == 0){
        p->queue_level = 0;
        p->qticks = 0;
      }
    }
  }
  release(&ptable.lock);
}

----- sysproc.c - sys_set_priority() -----
// ---- Assignment 3 Q2 / Assignment 7 Q4: set_priority(int pid, int pri)
// Priority range is fixed by the PDF: 1 = highest .. 20 = lowest. ----
int
sys_set_priority(void)
{
  int pid, pri;
  if(argint(0, &pid) < 0 || argint(1, &pri) < 0 || pri < 1 || pri > 20)
    return -1;
  return set_proc_field(pid, pri, 1);
}

----- priotest.c - complete test program -----
// Assignment 3, Question 2 / Assignment 7, Question 4 test: preemptive
// priority scheduling with aging (single implementation, two labels).
// Build and run with: make qemu SCHED=PRIO CPUS=1
// Expected: the high-priority (low number) child finishes first even
// though it was created last; the starved child still completes thanks
// to aging (its priority improves after AGING_INTERVAL ticks waiting).
#include "types.h"
#include "stat.h"
#include "user.h"
#include "pinfo.h"

static void work(int me)
{
  volatile int i, x = 0;
  for(i = 0; i < 80000000; i++) x += i;
  struct pinfo pi;
  getpinfo(&pi);
  printf(1, "prio: child %d done (pid %d, priority %d)\n",
         me, pi.pid, pi.priority);
  exit();
}

int
main(void)
{
  set_burst(getpid(), 80);
  if(fork() == 0){ set_priority(getpid(), 18); work(0); }   // low priority, created 1st
  if(fork() == 0){ set_priority(getpid(), 10); work(1); }   // mid priority
  if(fork() == 0){ set_priority(getpid(), 2);  work(2); }   // high priority, created last
  wait(); wait(); wait();
  printf(1, "prio: test complete\n");
  exit();
}

IN THE LAB: WHAT TO DO AND WHAT TO SHOW
---------------------------------------
Follow how sched_tick() ratchets priority down (number) after AGING_INTERVAL and resets ready_since. Run priotest and screenshot.

HOW IT IS IMPLEMENTED
---------------------
Add priority to proc.h with default 10. Wire the set_priority syscall end to end: a number in syscall.h, a stub in usys.S, a declaration in user.h, a table entry in syscall.c, the implementation in sysproc.c. The scheduler picks the lowest priority number, and a per-tick routine raises a waiting process one level after 30 ticks.
