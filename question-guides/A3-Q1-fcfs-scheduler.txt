xv6 OS LAB - ASSIGNMENT 3, A3 Q1: FCFS scheduler
================================================================

WHAT THE QUESTION ASKS
----------------------
Replace the round-robin scheduler with non-preemptive first-come-first-served: a ctime field set from ticks in allocproc(), and a scheduler that always picks the RUNNABLE process with the smallest ctime and lets it finish.

HOW TO BUILD AND RUN
--------------------
Build and boot:   make clean && make SCHED=FCFS qemu CPUS=1
At the xv6 shell: fcfstest

WHICH FILES TO OPEN / SHOW
--------------------------
proc.c (key() and pick()), proc.h (ctime), trap.c (no timer yield under FCFS)

EXPECTED OUTPUT
---------------
Three staggered children finish strictly in creation order: child 0, then 1, then 2 (verified).

----- proc.c - pick() -----
static struct proc*
pick(void)
{
  struct proc *p, *best = 0;
  uint bkey = 0;

  for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){
    uint k;
    if(p->state != RUNNABLE)
      continue;
    if(SCHED == SCHED_MLFQ){
      // A4 Q3: never pick a lower queue while a higher queue has work.
      if(best != 0){
        if(p->queue_level > best->queue_level)
          continue;
        if(p->queue_level == best->queue_level &&
           p->last_run >= best->last_run)
          continue;
        best = p;
      } else {
        best = p;
      }
      continue;
    }
    k = key(p);
    if(best == 0 || k < bkey || (k == bkey && p->last_run < best->last_run)){
      best = p;
      bkey = k;
    }
  }
  return best;
}

----- proc.c - sched_charge() (0 = never preempted) -----
// Charge one tick of runtime and apply per-policy quantum accounting.
// Called from trap.c while handling a timer interrupt on a RUNNING proc.
// Returns 1 when the policy wants the CPU back (preemption).
int
sched_charge(struct proc *p)
{
  p->rtime++;
  p->qticks++;
  switch(SCHED){
  case SCHED_SRTF:                     // A4 Q1
    if(p->burst_time >= 0 && p->remaining_time > 0)
      p->remaining_time--;
    return 1;                          // re-pick every tick
  case SCHED_MLFQ: {                   // A4 Q3: demote at quantum expiry
    int limit = p->queue_level == 0 ? MLFQ_Q0_TICKS :
                p->queue_level == 1 ? MLFQ_Q1_TICKS : MLFQ_Q2_TICKS;
    if(p->qticks >= limit){
      if(p->queue_level < MLFQ_LEVELS - 1)
        p->queue_level++;
      p->qticks = 0;
    }
    return 1;
  }
  case SCHED_RR:
  case SCHED_PRIO:                     // A3 Q2/A7 Q4: preemptive, quantum 1
    return 1;
  case SCHED_FCFS:                     // A3 Q1: non-preemptive
  case SCHED_SJF:                      // A3 Q3: non-preemptive
  case SCHED_HRRN:                     // A4 Q2: non-preemptive
  default:
    return 0;
  }
}

----- fcfstest.c - complete test program -----
// Assignment 3, Question 1 test: FCFS (first come first served).
// Build and run with: make qemu SCHED=FCFS CPUS=1
// Expected: children finish strictly in creation order (c0, c1, c2),
// even though each gets the same CPU work.
#include "types.h"
#include "stat.h"
#include "user.h"
#include "pinfo.h"

static void work(int me)
{
  volatile int i, x = 0;
  for(i = 0; i < 50000000; i++) x += i;
  struct pinfo pi;
  getpinfo(&pi);
  printf(1, "fcfs: child %d done (pid %d, rtime %d)\n", me, pi.pid, pi.rtime);
  exit();
}

int
main(void)
{
  int i;
  set_burst(getpid(), 50);
  for(i = 0; i < 3; i++)
    if(fork() == 0)
      work(i);
  for(i = 0; i < 3; i++)
    wait();
  printf(1, "fcfs: test complete\n");
  exit();
}

IN THE LAB: WHAT TO DO AND WHAT TO SHOW
---------------------------------------
Read key() in proc.c and see why sched_charge() returns 0 for FCFS (never preempted). Run fcfstest, screenshot the completion order.

HOW IT IS IMPLEMENTED
---------------------
Add ctime to struct proc in proc.h and set it from ticks in allocproc(). In the scheduler loop, scan for the RUNNABLE process with the smallest ctime instead of taking the next in round-robin order, and never yield on a timer tick, so the chosen process runs to completion.
